# خارطة Diskoko: 100 ترتيبًا وميزة لتجربة مترابطة

هذه الخارطة ليست قائمة أزرار منفصلة؛ بل نظام واحد يبدأ من الحساب، يختار سيرفرًا، يدخل إلى مساحة السيرفر، ثم ينتقل إلى Studio لتنفيذ تغييرات قابلة للمراجعة.

## أولًا: الهيكل والتنقل

1. جعل لوحة الحساب نقطة البداية الوحيدة بعد تسجيل الدخول.
2. جعل اختيار السيرفر إلزاميًا قبل أدوات التعديل والتنفيذ.
3. توحيد اسم الكيان في كل الواجهات: «السيرفر» ثم «مساحة السيرفر».
4. تقسيم Studio إلى: الرئيسية، البناء والتعديل، البوتات، الأتمتة، الأمان، التحليلات، السجل، الإعدادات.
5. إزالة التنقلات الفرعية المتكررة والمتنافسة.
6. إظهار اسم السيرفر الحالي في رأس كل شاشة.
7. إضافة مسار رجوع واضح إلى لوحة الحساب.
8. حفظ آخر سيرفر وآخر شاشة آمنة للمستخدم.
9. دعم روابط عميقة تفتح السيرفر والشاشة مباشرة.
10. إضافة حالة «أين أنا؟» عبر Breadcrumb واضح.
11. إظهار الخطوة التالية بدل عرض كل الخيارات دفعة واحدة.
12. تجميع الإجراءات حسب نية المستخدم لا حسب التقنية.
13. توحيد المصطلحات العربية والإنجليزية في جميع الصفحات.
14. منع فتح أدوات التنفيذ دون تحقق الربط والصلاحيات.
15. إضافة شاشة فارغة مفيدة لكل قسم غير مستخدم.

## ثانيًا: لوحة الحساب

16. ملخص حالة الحساب والخطة في بطاقة واحدة.
17. قائمة سيرفرات قابلة للبحث والفرز.
18. فلتر: جاهز، يحتاج تثبيتًا، صلاحيات ناقصة، فشل تحقق.
19. بطاقة سيرفر تعرض الإجراء الرئيسي فقط أولًا.
20. وضع أزرار التعديل والإدارة والإحصائيات داخل مساحة السيرفر.
21. زر «إنشاء سيرفر جديد» يشرح قيد Discord بوضوح.
22. مزامنة السيرفرات مع حالة تحميل واضحة.
23. عرض سبب عدم الجاهزية بلغة مفهومة.
24. إظهار آخر تحقق من البوت.
25. إظهار سعة الخطة المستخدمة والمتبقية.
26. اختصار مباشر إلى Studio بسياق `guild`.
27. عرض آخر مسودة لكل سيرفر.
28. عرض آخر خطة تغييرات وحالتها.
29. عرض آخر فشل مع إجراء إصلاح.
30. عرض عدد الأوامر والعمليات الشهرية.
31. إضافة مركز إشعارات للحالات المهمة.
32. إضافة تعليمات بداية للمستخدم الجديد.
33. حفظ تفضيل اللغة والمنطقة الزمنية.
34. تحسين حالات الخطأ وإضافة إعادة المحاولة.
35. دعم الوصولية ولوحة المفاتيح.

## ثالثًا: مساحة السيرفر

36. رأس ثابت يوضح اسم السيرفر وحالته.
37. تبويب «ملخص» للأرقام التشغيلية.
38. تبويب «البناء» للقنوات والتصنيفات.
39. تبويب «الرتب والصلاحيات».
40. تبويب «البوتات والأوامر».
41. تبويب «الأتمتة».
42. تبويب «الأمان».
43. تبويب «السجل».
44. عرض صلاحيات البوت المطلوبة والموجودة.
45. فحص هرمية الرتب قبل عمليات الرتب.
46. فحص صلاحيات القنوات قبل التعديل.
47. زر إعادة التحقق يدويًا.
48. عرض حالة تثبيت Diskoko.
49. إظهار حالة آخر اتصال للبوت.
50. إظهار عدد القنوات والتصنيفات والرتب.
51. إظهار الأعضاء التقريبيين مع تعريف المصدر.
52. إظهار خطط التغيير الأخيرة.
53. إظهار المسودة الحالية.
54. زر تصدير تصميم السيرفر.
55. زر فصل السيرفر مع تحذير واضح.

## رابعًا: Studio والبناء

56. شاشة بداية تسأل: ماذا تريد أن تبني؟
57. اختيار قالب متخصص بدل نموذج فارغ فقط.
58. معاينة قبل الحفظ.
59. محرر تصنيفات وقنوات مرتب وسهل السحب مستقبلًا.
60. محرر رتب وصلاحيات منفصل.
61. إعدادات افتراضية محافظة لا تحذف شيئًا.
62. تمييز الموارد الجديدة والمعدلة والمتعارضة.
63. إنشاء Change Set قبل التطبيق.
64. عرض عدد العمليات قبل الموافقة.
65. دعم حفظ المسودة خادميًا.
66. دعم استعادة آخر مسودة.
67. دعم نسخ التصميم.
68. دعم مقارنة نسختين.
69. منع التغييرات الخطرة دون تأكيد ثانٍ.
70. عرض نتيجة كل عملية بعد التنفيذ.
71. دعم إعادة المحاولة للعملية الفاشلة فقط.
72. دعم الاستئناف بعد Rate Limit.
73. عرض ما لا يمكن عكسه قبل التطبيق.
74. منع حذف الموارد في المسار الأول.
75. ربط كل تغيير بسجل تدقيق.

## خامسًا: البوتات والأوامر

76. قسم Bot موحد بدل صفحات بوتات متناثرة.
77. كتالوج وظائف واضح: مساعدة، ترحيب، أمان، فعاليات.
78. شاشة اختيار الأوامر حسب المجموعة.
79. عرض صلاحية كل أمر.
80. إعداد قناة الأوامر.
81. إعداد لغة البوت.
82. إعداد قناة السجل.
83. تفعيل الموافقة البشرية افتراضيًا.
84. منع حفظ Token في المتصفح.
85. فحص حالة تسجيل الأوامر.
86. عرض الأوامر المسجلة والفاشلة.
87. دعم إعدادات مستقلة لكل سيرفر.
88. عرض آخر تفاعل للبوت.
89. زر اختبار آمن لا يغير الموارد.
90. سجل إعدادات البوت.

## سادسًا: الأمان والتحليلات والجودة

91. مركز أمان موحد.
92. ملخص مخاطر قابل للفهم.
93. سياسات مكافحة السبام والروابط.
94. سياسة حماية الانضمام.
95. تنبيهات عند سحب الصلاحيات.
96. تحليلات مبنية على أحداث فعلية لا أرقام وهمية.
97. تعريف واضح للأوامر النشطة خلال 30 يومًا.
98. تقارير قابلة للتصدير.
99. اختبارات واجهة ومسارات API قبل كل نشر.
100. نظام نقاط جودة يراجع الربط، الصلاحيات، المسودة، الخطة، والسجل قبل اعتبار السيرفر جاهزًا.

## ترتيب التنفيذ

تُنفذ البنود على دفعات: **الدفعة الأولى** توحيد التنقل والحساب ومساحة السيرفر؛ **الدفعة الثانية** البناء والمسودات وخطط التغيير؛ **الدفعة الثالثة** البوتات والأتمتة؛ **الدفعة الرابعة** الأمان والتحليلات والجودة. لا تُعرض ميزة على أنها تنفيذ حقيقي إذا كانت ما تزال معاينة محلية.
